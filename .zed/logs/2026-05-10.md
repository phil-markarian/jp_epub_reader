## Toolchain gotcha — rustup vs brew rust

User has both `brew install rust` (standalone toolchain) AND
`brew install rustup` (proxy installer). The brew rust formula puts a
real `cargo`/`rustc` in `/opt/homebrew/bin/`, while rustup proxies live
at `/opt/homebrew/opt/rustup/bin/`. If the rustup proxies aren't first
in PATH, brew rust shadows rustup, and brew rust doesn't have the
`wasm32-unknown-unknown` target installed → wasm builds fail.

In my (Claude Code) Bash tool environment the PATH didn't include
`/opt/homebrew/opt/rustup/bin/`, so `cargo build --target=wasm32...`
via `trunk` failed. Workaround: I prepend
`$HOME/.rustup/toolchains/stable-aarch64-apple-darwin/bin` for
verification. The user's fish shell gets it right via some conf.d
mechanism — `cargo tauri dev` works there.

If this becomes annoying: `brew uninstall rust` (keep rustup), or add
`/opt/homebrew/opt/rustup/bin` to PATH ahead of `/opt/homebrew/bin`
in fish config.
